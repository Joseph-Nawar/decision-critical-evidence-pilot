# Novelty risks and claims permitted by this pilot

Audit date: 2026-11-18 (Africa/Cairo). This is a scientific scope assessment, independent of the pilot's eventual empirical verdict. The source-backed details and implementation checks are in [`LITERATURE_MATRIX_VERIFIED.md`](LITERATURE_MATRIX_VERIFIED.md); retrieval receipts are in [`results/literature/`](../results/literature/).

**No positive algorithmic novelty claim is supported.** The pilot is research triage. Successful execution could justify a focused follow-up benchmark experiment; it cannot, by itself, establish that existing methods fail or that a new selector is needed.

## The deterministic-query alternative is decisive

The task generator intentionally provides explicit policy and structured records. A deterministic query/policy interpreter can be the appropriate production architecture for precisely that interface. Its success would be a scientifically meaningful null result for a general LLM-selector proposal.

The comparison must disclose its privilege: it receives machine-readable workflow specifications, schema and authorized observed records. If the model is asked to infer a specification that the interpreter already receives as code, the difference reflects interface and engineering assumptions. If the deterministic system has hidden-state access, it becomes an oracle and invalidates the comparison. For incomplete data, it must obey the same completeness/recovery contract; a full backing database is not automatically authorized observed evidence.

Do not manufacture novelty by adding artificial identifiers, adversarially arranging irrelevant rows, or withholding the query language that a realistic system would have. Any residual failure must be valuable under a plausible deployment interface.

## What the present baseline grid can and cannot establish

B0/B1/B3 can measure losses from the implemented truncation and lexical policies. B4 can reveal that these workflows need no model-based evidence selector. B6 bounds evidence-access effects. Generic B5 is a transparent fallback comparator, not a faithful Squeez, LLMLingua-2, DTOC or TreeAgent run. It cannot support “existing compression fails” or “our method beats the state of the art.”

Distinguish source availability from reproduction: inspected code may still require checkpoints, callbacks, paid inference, data permissions or missing frozen artifacts. None of the source-audit paper results was independently rerun. Public source does not imply a permissive license, and a paper license does not cover every repository or upstream dataset.

An oracle-versus-model gap alone is insufficient. Require a competent full-evidence arm, paired coverage, and decomposition into lost evidence, evidence-present reasoning, output/schema failure and policy/deferral error. Critical-evidence recall is a diagnostic whose annotation must stay private. Completeness is part of sufficiency for negative and aggregation outcomes, not an optional lexical feature.

## Unanswered questions and decision implications

1. Does a real policy-driven workflow remain after deterministic querying has been granted the same public inputs and realistic engineering investment?
2. Does the failure persist when evidence access is reversible and all recovery calls are charged to a common resource account?
3. Does explicit coverage metadata merely expose the correct action directly? Counterfactuals must keep the question and observed facts fixed where possible and vary coverage alone, without answer labels in inputs.
4. Can a coverage intervention change an executed state decision while avoiding confounding by general small-model incompetence?
5. Would an existing learned compressor preserve the relevant dependencies at the same actual token budget? This pilot's byte budget does not answer that question by itself.
6. Are gains robust to realistic record ordering and ambiguity, rather than generator-specific shortcuts? Held-out performance cannot be used to retrofit the generator.

If B4 solves essentially all valid cases under fair access, recommend NO-GO for a broad selector project on this task class. If full-context models cannot reliably execute the policy, selection effects are not isolated; a larger selection project is not justified by that gap. Missing minimum coverage or indispensable comparisons supports INCONCLUSIVE, not a fabricated negative result.

If a focused effect survives the pilot, the smallest defensible next experiment is a **paired coverage intervention on one negative-evidence workflow**: fixed observed facts and question; complete versus partial query-relative coverage; executed allow/reject/defer actions; full evidence, deterministic query, lexical selection and a reversible recovery arm with equal access and total-call accounting. This is a candidate next experiment, not a claim that completeness reasoning or recovery is novel. Adding a faithful released compressor would be required before broad comparative claims.

## Literature limits

The eight supplied sources and two additional primary precedents were verified, but this is not an exhaustive systematic review. Displayed submission-date inconsistencies were retained in the matrix. Discovery Science proceedings status was not independently verified; CROWN-QA public artifact/license remain unverified. Exact package versions, model checkpoints and host integrations would need separate pinning for replication. No novelty claim rests on inaccessible code, chronology ambiguities, or absence of a discovered URL.
